MERGE SORT VISUALIZER

MAIN COMPONENTS:

 1. input container for user input
 2. main sorting container for sorting the unsorted list

BUILDING ROUTE:

1. An app header --> "MERGE SORT VISUALIZER" & a sub-header --> "Sorting Algorithms Made Easy".

2. In the main section there should be two div containers:
   
   i) Frist container is for getting user input: 
      
       a) Input shold be an array of ascending numbers & this crieteria sholud be provided to the user as "(Please Enter The Numbers)"
       
       b) As the user input each number it should be added to the actual array (You can assume it like an queue) inside the acual visualizing container beside the input container.
       
       c) In the input container there should be :
          
            > A text-box (input-box) where the user can give input the numbers, with a label --> "Numbers Only"  
            > Under that there should be an insert button (for inserting the number in the array)
            > Under that there should be an delete button (for deleting a number if user wanted)
   
   ii) Second container for the atual sorting algorithm visualzer:
     
     a) At the top of the visualiztion container ther should be two headings "The Visualizer" & "Total Elements = {The total nuber of elements the user has enterd}", they should be palced at the top far left and top far right corners respectively.  
       
     b) The inputed array should be visible with their indices starting from 0
     
     c) The actual array be visible & it should grow as new elements are inputed by the user, also the indices.

     d) Under that there should be a button with the label "Begin Sort"

     e) As the user hit that button the actual search should begin:
        With each iteration the actual logic of binary search should be visible, that is:
        > Implementing the Divide & Conquer Rule
        > The array sholud be divided from an element with each iteration
        > All the sub-arrays should be connected to the actual array they come from by means of lines, building a tree like structure
        > After sorting of the elements are done they should merge in a single sorted array with indices.
        > The mid point/ the element from which the array is sub-divided, should glow in sea-green color
        > The sort should always produce sorted elements in ascending order  
      
     f) After the sorting is done; in the visualization container a success msg with the details of the sorting should be displayed:
        > The Sort is Done
        > Total comparison(s): {the total number of comparisons} | Time taken: {time taken to complete the searching in miliseconds(ms)}
        > Time Complexity: {Merge Sort Time Complexity: O(nlogn)} | Space Complexity: {Space Complexity of Merge Sort: O(n)}
  
     g) Button For Fresh Sorting:
         > There should also be a button for begin a new sorting with the lable "Begin New Sort"
         > If the user hit the button everything should reset to normal, for a new sorting operation

3. Special Cases:
   > User hit the "Begin Sort" button without entering any element, then a msg should be displayed "Please Enter Numbers" & the input container's border should glow.
   > In the middle of a sorting opration if the user hit the "Begin New Sort" button the page should give an alert with msg "A sort is going on, Please Wait" & as the user hit the ok button in the alert the search should continue as usal.
   > If the user enter an already sorted array(ascending order) then a msg should be displayed --> "The List is already Sorted"
   > The app should work on pc, laptop, smart-phones, any browser, slim-phones, i-phones, mac-books; so please add the neccessary @media updates/coding in the css file
